What this project does

It asks one question: can a computer look at a single stitch and give it an interpretable quality score from 1 to 5, explained by measurable geometry? The work is organised as three notebooks and one reusable Python package, using the SutureBot2 robotic suturing dataset.

What it CAN claim. The hybrid model predicts the stitch-quality target accurately and far better than an image-only model; the geometry gives human-readable reasons; grouped evaluation exposes generalization.
What it CANNOT claim. These scores are a geometric-consistency proxy, not clinical quality. SutureBot2 has no expert 1–5 ratings. Nothing here predicts healing or rates a surgeon.

Notebook 1 — the 10 preprocessing steps (cell by cell)

  1. Verify folders. Confirm the dataset layout exists before doing anything.
  2. Manifest + path rewrite. Read the author file list and rewrite their absolute paths to local paths.
  3. Frame inventory. List every frame; flag which have masks, boxes, and which are empty "negatives".
  4. Bounding-box validation. Reject impossible boxes (wrong size, NaN, zero/negative area).
  5. Stitch instances. One row per valid box → the unit the model scores (919 rows).
  6. Action context. Join the human sub-task label active at each stitch's frame.
  7. Geometry features. Compute wound-relative numbers: box size, centre, distance to wound boundary, overlap, spacing, needle alignment.
  8. Padded crops. 20% padding around each box → resized 224×224 image.
  9. Grouped splits + proxy target. Split by episode (train 561 / val 143 / test 215) and derive the 1–5 geometric proxy, with thresholds fitted on train only.
  10. Audit. Counts, distributions, leakage check and an annotation overlay figure.
Why "grouped" splits matter. Frames from one stitching episode are near-duplicates. If they land in both train and test, the model "memorises" and the score looks fake. So we split by episode, never by frame — and prove it with a leakage check.

How it was used here

  • Only the 5 annotated batches (fausto_0/1, jesse_0/1/2) have masks + stitch boxes → they drive the scoring. The 5 DAgger batches have no masks/boxes → not used for stitch scoring.
  • 853 endoscope frames → masks + boxes → expanded to 919 stitch instances.
  • Masks → wound-relative geometry (the explainable features).
  • Boxes → padded 224×224 crops → the image branch.
  • labels.jsonl → sub-task context per stitch.
  • insertion_exit_points.csv → needle alignment features.
  • LeRobot parquet (robot poses) → stored and readable, but not yet used as model input (available for future work).
  • Videos → defined in the dataset but not downloaded locally (only the 853 sampled frames are present).
  • The target is derived: a transparent geometric-consistency proxy, because no expert ratings exist.
03

Models used

The proposed model is called the "Dale" model — a geometry-dominant hybrid ordinal network. Everything else is a baseline or an ablation.

ResNet18 (frozen)

The "eyes". A standard ImageNet-pretrained ResNet18 (11.7M params) turns each 224×224 stitch crop into a 512-number embedding. It is frozen — never trained — so the small data can't overfit it and embeddings are computed once.

role: feature extractor

Dale model (proposed)

Residual hybrid fusion: geometry is the backbone, and the image adds a small, bounded, learned correction (gate initialised small). A CORAL head outputs an ordered 1–5 score. Trained as a 6-seed ensemble (probabilities averaged).

role: the contribution

Baselines / ablations

Geometry-only (ordinal logistic + random forest), image-only (same head as the hybrid), and a YOLO detection baseline (localization only; not installed → reference). Used to prove the fusion earns its keep.

role: fairness checks

Model architecture (how the Dale model thinks)

Because the image only adds a small bounded correction, the hybrid can never fall far below a geometry-only model — it can only improve on it. That is what fixed the earlier result where geometry-alone beat the hybrid.

05

Evaluation protocol (the complete flow)

Four evaluations are run, from easiest to hardest. The harder ones are what a reviewer trusts.

Exact vs within-one. Exact = the score is bang on. Within-one = bang on or one away. A one-step miss on an ordered 1–5 rating is a mild error, which is why within-one is reported.
Confidence intervals. Metrics come with grouped-bootstrap 95% intervals — episodes are resampled (not stitches), keeping correlated stitches together.

07

Overfitting & leakage audit

Because within-one hit 100%, the pipeline was audited for leakage and overfitting.

Leakage — clean

  • Splits grouped by episode; leakage check: 0 leaked groups.
  • Geometry scaler fitted on train only.
  • Proxy thresholds fitted on train only.
  • ResNet18 is frozen → no fitting, no leakage.
  • 5-fold grouped CV brackets the test score → stable.

Verdict: no data leakage found.

Overfitting — a real but moderate gap

SplitExact %MAE
train99.50.005
validation85.30.154
test82.30.177

Train ≈ perfect, test ≈ 82–85% → the model partly memorises the small train set (expected, since the label is deterministic geometry). Validation ≈ test, so it does generalise to unseen episodes.

Why within-one is 100% — and it is not cheating. The 1–5 target is a deterministic, quantile-binned function of geometry, so a geometry-dominant model reproduces the ordering almost perfectly and errors are almost never ≥ 2. Even the geometry-only baseline scores 100% within-one. This is label circularity (inputs and label both come from geometry), not leakage.
The honest number is cross-operator. When a whole operator's batch is held out (leave-one-batch-out), exact accuracy drops to 68–79%. That is the generalization figure to trust in the paper.
08

What changed in this work

The model improved

Original hybrid exact accuracy was 65.6% and it lost to the geometry-only baseline. Switch to a geometry-dominant residual fusion + 6-seed ensemble → 85.1% exact, and it now beats every baseline.

Notebooks rebuilt

All three notebooks are now cell-by-cell with plain-English explanations, inline code comments and rich inline visuals; every figure is produced and saved; a results table and an overfitting/leakage audit cell were added.
